# 如何管理单词

这份文档写给 **Agent**（以及任何直接改文件的工具）：告诉你词库放在哪、
JSON 长什么样、**哪些字段必须有、哪些可以没有**、怎么加新篇章和新单词。

改完**不需要重新编译 APK** —— 数据在公共目录，App 重启即生效。

---

## 0. 一句话总览

```
一本书 = 若干章
一章   = 若干张卡 + （可选）一篇语篇
一张卡 = 必须有 word + senses（词 + 词义）
         其余全部可选：音标、例句、派生词、近反义词、各种扩展块
```

**核心原则：少写东西不会崩。**

只有 `word` 和 `senses` 是硬要求。音标、例句、派生词、近义词、反义词、
词根词源、常用短语……**缺哪个都不影响渲染**，缺的部分界面上直接不显示。

唯一的功能性后果：

> **没有例句 → 这张卡不出「选词填空」**（空挖不出来），
> App 会自动跳过这个考法，只考选义，卡片照常毕业。

## 2. 三步加一本新书

1. 写一个 JSON 文件（结构见第 3 节），文件名随便，比如 `my_words.json`。
2. 丢进 `Documents/Flashcard/books/`。
3. 重启 App（或回到首页下拉/重进书库）。

App 会自动：
- 拆成分片目录 `books/my_book/`
- 原文件改名 `my_book.json.bak`
- 在书库里显示出来

## 3. 一本书的 JSON 结构

### 3.1 顶层

```json
{
  "schema": 2,
  "book_id": "my_book",
  "title": "我的单词本",
  "subtitle": "随手记 · 2026",
  "template": "bubei_dark",
  "fields_order": ["word", "syllable", "phonetic_us", "phonetic_uk", "senses",
                   "derivatives", "synonyms", "antonyms",
                   "sentence_en", "sentence_cn", "blocks", "exam_tag"],
  "chapters": [ ... ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema` | 建议 | 格式版本，当前 **2**。老格式（没有 senses/blocks）也能读 |
| `book_id` | ✅ | 书的唯一 ID，**只用字母数字下划线**，决定目录名 |
| `title` | ✅ | 书名，显示在书库 |
| `subtitle` | | 副标题 |
| `template` | ✅ | 用哪个模板，一般 `bubei_dark` |
| `fields_order` | | 字段顺序提示，不影响功能，照抄上面的即可 |
| `chapters` | ✅ | 章节数组，至少一章 |

> 也兼容老的单文件平铺格式（顶层直接 `cards`，没有 `chapters`），
> 但**新写的请用 `chapters`**。

### 3.2 一章

```json
{
  "chapter_id": "ch01",
  "title": "第一章 · 高频核心词",
  "passage": { ... },
  "cards": [ ... ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `chapter_id` | ✅ | 章唯一 ID，如 `ch01` |
| `title` | ✅ | 章名，复习时顶部会显示 |
| `passage` | | 语篇（见 3.3）。一章最多一篇。没有就不挖空，直接背单词 |
| `cards` | ✅ | 这一章的卡片数组 |

**复习是严格按「书 → 章」逐章推进的**，每章用自己的语篇。
所以**一章的语篇里出现的词，应该就是这一章卡片里的词**。

### 3.3 语篇（passage）

```json
{
  "title": "A Tight New Policy",
  "text": "The company tried to [impose] a strict new policy. The [inherent] problems made it hard to [comply], but cooler heads [prevailed|prevail].",
  "cn": "公司试图[强加]一项严格的新政策。[固有]的问题让人难以[遵从]，但冷静的一方[占了上风]。"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | | 语篇标题 |
| `text` | ✅ | 英文正文，目标词用方括号标出（见下） |
| `cn` | | 中文翻译，可同样用方括号标出对应词 |

#### 语篇标记语法（重要）

| 写法 | 含义 |
|---|---|
| `[impose]` | 文中就是这个单词的**原形** |
| `[prevailed\|prevail]` | 竖线前是**文中变形**，竖线后是**词条原形** |

App 只挖「今天到期 / 今天新学」的那些词对应的空；
其他标记词会**显示为带下划线的词**，点击可看释义，但不挖空、不进词库。

> 如果语篇里的词在本章**没有对应卡片**，它就不会被挖空（只当下划线词）。
> 所以语篇用词要和本章卡片对得上。

### 3.4 一张卡

**最小可用**（只有词 + 词义，别的什么都没有 —— 这完全合法）：

```json
{
  "word": "intensive",
  "senses": [
    { "pos": "adj.", "cn": "密集的，加强的；(农业)集约的" }
  ]
}
```

**完整一点**（把可选项都填上）：

```json
{
  "word": "intensive",
  "syllable": "in·ten·sive",
  "phonetic_us": "/ɪnˈtensɪv/",
  "phonetic_uk": "/ɪnˈtensɪv/",
  "exam_tag": "考研高频词 · 真题出现 18 次",

  "senses": [
    { "pos": "adj.", "cn": "密集的，加强的；集约的" }
  ],

  "derivatives": [
    { "word": "intensively", "senses": [ { "pos": "adv.", "cn": "密集地，集中地" } ] },
    { "word": "intensify",   "senses": [ { "pos": "vt.", "cn": "加强，加剧" },
                                          { "pos": "vi.", "cn": "增强，变强" } ] }
  ],

  "synonyms": [
    { "word": "concentrated", "senses": [ { "pos": "adj.", "cn": "集中的，浓缩的" } ] }
  ],
  "antonyms": [
    { "word": "extensive", "senses": [ { "pos": "adj.", "cn": "广泛的，广博的" } ] }
  ],

  "sentence_en": "The course requires <u>intensive</u> study over a short period.",
  "sentence_cn": "这门课程要求在短时间内进行高强度学习。",

  "blocks": [
    { "type": "html", "title": "词根词源",
      "html": "<b>in-</b> (进入，深入) + <b>tens</b> (拉紧) + <b>-ive</b> → 朝里极度拉紧的" }
  ]
}
```

## 4. 字段详解

### 4.0 【最重要】哪些必须有、哪些可以没有

| 字段 | 必填？ | 缺了会怎样 |
|---|---|---|
| `word` | ✅ **必须** | 没有就不叫单词卡了 |
| `senses` | ✅ **必须** | 没有词义 → 不出「选义」考法 |
| `sentence_en` | 可选 | 没有 → **不出「选词填空」**，其余照常 |
| `syllable` | 可选 | 词义页大字退化成 `word` |
| `phonetic_us` / `phonetic_uk` | 可选 | 音标胶囊不显示（点击发音仍然可用） |
| `sentence_cn` | 可选 | 例句中文那行不显示 |
| `exam_tag` | 可选 | 左上角角标不显示 |
| `derivatives` | 可选 | 派生词卡片不显示 |
| `synonyms` / `antonyms` | 可选 | 近反义词卡片不显示 |
| `blocks` | 可选 | 扩展卡片区不显示 |
| `passage` | 可选 | 这章直接背单词，不走语篇 |

> **写卡的口径**：能写就写例句和词义，派生词 / 近反义词**有就写、没有别硬凑**。
> 短语搭配、词根词源更是随缘 —— 见 4.4 末尾的「别刻板化」。

### 4.1 固定字段（引擎要读，必须按这个来）

这些字段**不能改名、不能改成别的形状**，因为 App 的背诵逻辑要用它们：
TTS 发音、判分、挖空、生成选项。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `word` | string | ✅ | **词条原形**。判分、TTS、和语篇标记匹配都靠它 |
| `senses` | array | ✅ | **义项列表**，见 4.2。一词多义 / 一词多性就靠它 |
| `syllable` | string | | 音节切分，如 `in·ten·sive`。词义页大字用，没有就用 word |
| `phonetic_us` | string | | 美音音标，如 `/ɪnˈtensɪv/`。带不带斜杠都行 |
| `phonetic_uk` | string | | 英音音标 |
| `sentence_en` | string | | 英文例句，**建议用 `<u>词</u>` 标出目标词**，见 4.5 |
| `sentence_cn` | string | | 例句中文翻译 |
| `exam_tag` | string | | 角标，如「考研高频词 · 真题出现 18 次」。没有就不显示 |

### 4.2 `senses` —— 义项列表（一词多义的关键）

**每个义项一个对象**，不要再用一个字符串硬凑。

```json
"senses": [
  { "pos": "adj.", "cn": "模糊的；晦涩难懂的；无名的" },
  { "pos": "vt.",  "cn": "使模糊；遮蔽" }
]
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `pos` | | 词性，如 `adj.` `vt.` `n.`。同一个词多个词性就写多条 |
| `cn` | ✅ | 这个义项的中文释义 |
| `phonetic_us` | | **多音词**才需要（如 record n./v. 读音不同），写在对应义项里 |

多个义项会：
- 在**词义页**逐条列出来（`adj. 模糊的…` / `vt. 使模糊…`）
- 在**选义 / 填空**里合并成一条纯中文提示

> **老格式兼容**：如果只有 `"pos": "adj."` + `"meaning": "密集的…"` 两个字符串，
> App 会自动折成一条 `senses`，不会出错。但新写的请用 `senses`。

### 4.3 派生词 / 近义词 / 反义词（**固定卡片**）

这三个是**固定字段，不是 block**。它们形状一致，都是
**「词 + 词性释义」绑定**，所以共用一套写法：

```json
"derivatives": [
  { "word": "intensively", "senses": [ { "pos": "adv.", "cn": "密集地，集中地" } ] },
  { "word": "intensify",
    "senses": [ { "pos": "vt.", "cn": "加强，加剧" },
                { "pos": "vi.", "cn": "增强，变强" } ] }
],

"synonyms": [
  { "word": "concentrated", "senses": [ { "pos": "adj.", "cn": "集中的，浓缩的" } ] }
],

"antonyms": [
  { "word": "extensive", "senses": [ { "pos": "adj.", "cn": "广泛的，广博的" } ] }
]
```

界面上：

| 字段 | 渲染成 |
|---|---|
| `derivatives` | 一张 **「派生词」** 卡片 |
| `synonyms` + `antonyms` | **同一张「近义词 / 反义词」卡片**，各带小标题 |

**关键点：**

- **多词性 = 多条 `senses`**，不要塞进一个字符串
  （`{"pos": "vt. / vi.", "cn": "…"}` 这种写法界面上会连在一起，不如拆开清楚）
- 每条**必须有 `word`**；释义没有也能显示（只有词的时候就不会带释义行）
- 词点一下会**发音**
- 三个字段**都可以没有**。没有 → 整张卡不显示，不留空壳

**简写也认**（写起来更短，App 会读成规范形）：

```json
"synonyms": [
  { "word": "concentrated", "pos": "adj.", "cn": "集中的，浓缩的" },
  "thorough"
]
```

### 4.4 `blocks` —— 展示块（扩展区）

这是**可选的扩展区**。词义页会按顺序把它们画成一张张卡片。
**加新字段不需要改模板、不需要重编 APK**，往 `blocks` 里加一个对象就行。

每个块都有两个通用字段：

| 字段 | 说明 |
|---|---|
| `type` | 渲染方式，见下表。**认不出来也不会崩**，会按内容退化渲染 |
| `title` | 块标题（会转成大写小字显示）。留空则不显示标题行 |

#### 支持的 type

| `type` | 用途 | 数据字段 | 例子 |
|---|---|---|---|
| `pairs` | 左右两列（短语搭配、词形对照） | `items: [{en, cn}]` 或 `[{k, v}]` | 常用短语 |
| `list` | 单列列表（易混词、补充说明） | `items: ["a", "b"]` 或 `[{en, cn}]` | 易混词 |
| `html` | 富文本，可带 `<b>` 等标签 | `html` | 词根词源、辨析说明 |
| `text` | 纯段落（内容会被转义，安全） | `text` | 一句话备注 |
| `table` | 表格（词形变化） | `cols: [...]`, `rows: [[...]]` | 动词变位 |
| `image` | 图片 | `src`, `alt` | 示意图 |

#### ⚠️ 别把「常用短语」刻板化

**不是每个词都有值得写的固定搭配。**

以前见过每张卡都硬塞一个「常用短语」块，结果里面写着
`intensive study`、`intensive care` 这种**根本不是固定搭配**的东西 ——
既占地方又没信息量。

正确的口径：

- **有真正的固定搭配才写**（`comply with`、`prevail over`、`take into account`）
- **没有就不写**，别为了「格式完整」硬凑
- 一个都没有 → 整个 `blocks` 都可以不要

> 同理适用于 `derivatives` / `synonyms` / `antonyms`：
> **有就写，没有就别写**。凑出来的东西比空着更糟。

#### 示例：一次把常用的都加上

```json
"blocks": [
  { "type": "pairs", "title": "常用短语",
    "items": [ { "en": "comply with", "cn": "遵守" } ] },

  { "type": "html", "title": "词根词源",
    "html": "<b>com-</b> (共同) + <b>ply</b> (折叠) → 折在一起 → 顺从" },

  { "type": "list", "title": "易混词", "items": ["compliment", "complete"] },

  { "type": "table", "title": "词形变化",
    "cols": ["原形", "过去式", "现在分词"],
    "rows": [["comply", "complied", "complying"]] }
]
```

> **`pairs` / `list` 的 items 写法很宽松**：
> `[{en, cn}]`、`[{k, v}]`、`[{left, right}]`、单个字符串、甚至单键对象都能认。
> 但**推荐 `{en, cn}`**，语义最清楚。

### 4.5 例句里的 `<u>` 标记（重要，别漏）

```json
"sentence_en": "The course requires <u>intensive</u> study over a short period."
```

- **建议用 `<u>…</u>` 把目标词圈出来**，包括变形：
  `"Common sense finally <u>prevailed</u> over panic."`（词条是 `prevail`）
- 词义页会把它渲染成**下划线高亮**
- **选词填空靠它精准抠空**：
  - 有 `<u>` 标记 → 直接把标记里那段挖成 `______`，变形词也不会漏
  - 没有标记 → 退回「原形整词匹配」，再退回「词干 + 常见后缀」兜底
  - 都匹配不上 → 空挖不出来

> 没标记不致命（会走兜底匹配），但**标了最稳**。
> 尤其变形词（`prevailed` / `complied` / `intensified`）一定要标。

### 4.6 不用再写的字段

| 老字段 | 现在怎么办 |
|---|---|
| `meaning` | 并进 `senses[].cn` |
| `pos` | 并进 `senses[].pos` |
| `meaning_plain` | **删掉**。App 自动从 `senses[].cn` 派生（会把括号里的短语剥掉） |
| `phrases` | 换成 `blocks` 里的一个 `pairs` 块（**真有搭配才写**） |
| `root` | 换成 `blocks` 里的一个 `html` 块 |

> 老数据 App 仍然能读（模板侧现场折算），但**新写的按新格式来**。

## 5. 为什么释义里不要带括号短语

选义 / 填空的选项会显示**纯中文释义**，用来让你选。

如果释义写成：

```
"cn": "盛行，流行；获胜，占优势 (prevail over/against)"
```

括号里的短语**带着答案本身**，等于把答案写在选项上。

**正确写法**：释义只写中文，短语放到 `blocks` 的「常用短语」里。

```json
"senses": [ { "pos": "vi.", "cn": "盛行，流行；获胜，占优势" } ],
"blocks": [
  { "type": "pairs", "title": "常用短语",
    "items": [ { "en": "prevail over", "cn": "战胜，压倒" } ] }
]
```

> App 也会自动剥掉括号内容做兜底，但**源头写干净最好**。

## 6. 校验清单（提交前自己过一遍）

- [ ] JSON 语法合法（逗号、引号、括号）
- [ ] `book_id` 只含字母数字下划线，且没和已有书重名
- [ ] 每张卡都有 `word`，且**全章唯一**
- [ ] 每张卡都有 `senses`，每个义项都有 `cn`
- [ ] 释义 `cn` 里**没有**括号短语（短语挪去 blocks）
- [ ] **有** `sentence_en` 的，里面标了 `<u>目标词</u>`（没有例句的卡可以整条不写）
- [ ] `sentence_en` 里的 `<u>` 内容是该词的**某种形式**（原形或变形都行）
- [ ] `derivatives` / `synonyms` / `antonyms` 每条都有 `word`，
      多词性拆成多条 `senses`（别写成 `"vt. / vi."` 一坨）
- [ ] 语篇 `text` 里的 `[词]` 在本章卡片里**存在**（否则不会被挖空）
- [ ] 语篇里的变形词用 `[prevailed|prevail]` 写，竖线后是词条原形
- [ ] `blocks` 每个块都有 `type`，且数据字段和 type 对得上

一行命令快速自检（在有 Python 的机器上）：

```bash
python3 - <<'PY'
import json, re, sys
d = json.load(open('my_words.json', encoding='utf-8'))
bad = []
words = set()

def rel_check(tag, w, arr):
    if arr is None: return
    if not isinstance(arr, list):
        bad.append('%s %s 不是数组' % (w, tag)); return
    for it in arr:
        if isinstance(it, str):
            if not it.strip(): bad.append('%s %s 有空字符串' % (w, tag))
            continue
        if not isinstance(it, dict):
            bad.append('%s %s 有非法条目' % (w, tag)); continue
        if not str(it.get('word', '')).strip():
            bad.append('%s %s 有条目缺 word' % (w, tag))
        sn = it.get('senses')
        if sn is not None and not isinstance(sn, list):
            bad.append('%s %s.%s senses 不是数组' % (w, tag, it.get('word')))

def check_card(c):
    w = c.get('word', '')
    if not w: bad.append('空 word'); return
    if w in words: bad.append('重复 word: ' + w)
    words.add(w)
    if not c.get('senses'): bad.append(w + ' 缺 senses')
    for s in c.get('senses') or []:
        if isinstance(s, dict):
            if not s.get('cn'): bad.append(w + ' 义项缺 cn')
            if re.search(r'[（(]', str(s.get('cn',''))):
                bad.append(w + ' 释义带括号短语')
    for tag in ('derivatives', 'synonyms', 'antonyms'):
        rel_check(tag, w, c.get(tag))
    se = c.get('sentence_en', '')
    # 没有例句是允许的（只是不出填空题）；有例句才要求标 <u>
    if se and not re.search(r'<u>.+?</u>', se):
        bad.append(w + ' 有例句但没标 <u>')

chapters = d.get('chapters')
if chapters:
    for ch in chapters:
        for c in ch.get('cards', []):
            check_card(c)
        p = (ch.get('passage') or {}).get('text', '')
        for m in re.finditer(r'\[([^\]|]+)(?:\|([^\]]+))?\]', p):
            lemma = (m.group(2) or m.group(1)).strip().lower()
            if lemma not in {x.lower() for x in words}:
                bad.append('语篇词不在本章卡片: ' + lemma)
else:
    for c in d.get('cards', []):
        check_card(c)

print('问题:', len(bad))
for b in bad[:40]: print('  -', b)
sys.exit(1 if bad else 0)
PY
```

## 9. 常见坑

| 现象 | 原因 | 怎么修 |
|---|---|---|
| 填空题没挖空、答案直接露出来 | 例句没标 `<u>`，且变形词匹配不上 | 给例句的目标词加 `<u>…</u>` |
| 选项一眼就能选出答案 | 释义里带了括号短语 | 短语挪到 `blocks`，释义只留中文 |
| 某张卡永远卡在重测里 | 早期版本：缺例句但还在考填空 | 已修（会话编排会跳过该考法）。若仍复现，检查 `word` / `senses` 是否为空 |
| 语篇里有些词不挖空 | 那些词在本章没有对应卡片 | 给它们补卡，或从语篇里去掉 |
| 语篇挖空的词和卡片对不上 | 用了变形但没写 `\|原形` | 写成 `[prevailed\|prevail]` |
| 派生词 / 近反义词不显示 | 字段名拼错，或数组为空 | 确认是 `derivatives` / `synonyms` / `antonyms`，且每条有 `word` |
| 近反义词里一个词的多词性挤成一坨 | 写成了 `"pos": "vt. / vi."` | 拆成多条 `senses` |
| 词义页少了几块内容 | `blocks` 里 `type` 拼错 | 对照第 4.4 节的 type 表 |
| 一词多性显示不全 | 只写了一条 `senses` | 每个词性写一条 |
| 新加的书不显示 | 权限没给 / JSON 语法错 / `book_id` 重复 | 看 App 设置页数据目录是否绿色；用第 6 节脚本自检 |

## 10. 给 Agent 的调用建议

1. **优先「读 → 改 → 写回」整个 JSON**，不要用正则硬改文本。
2. 写入前**先备份**原文件（如 `xxx.json.bak`）。
3. 用 **UTF-8 无 BOM** 写文件，中文直接写，不要转成 `\uXXXX`。
4. 保持 `indent=2`，方便人肉 diff。
5. 每次改动后跑一遍第 6 节的校验脚本。
6. **不要为了「格式完整」硬凑内容**：没有例句就不写例句，
   没有派生词就不写派生词，没有固定搭配就不写短语。
   空着比凑数好 —— 界面本来就会优雅地不显示。
7. 只往 `books/` 和 `templates/` 里写；`progress*.json` / `settings.json`
   是 App 的运行时状态，**不要碰**。
