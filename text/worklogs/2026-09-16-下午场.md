## 1. 阶段 0：双向 RPC 桥

### 1.1 新增 `app/lib/services/bridge_rpc.dart`

`BridgeRpc` = 方法注册表 + 回执/事件脚本生成。

- `register(method, handler)`：方法名 `域.动作`（`card.get` / `session.save` …）
- `dispatch(id, method, params)`：查表执行 → 生成回执脚本；**任何异常都兜成 `ok:false`**，一条坏请求打不断桥
- `resolveScript` / `emitScript`：复用 `TemplateEngine.jsonForJs` 做 JS 单引号转义

### 1.2 新增 `app/lib/services/session_store.dart`

workflow 断点存 `<公共目录>/Flashcard/session.json`。
只存「一个」当前会话（背单词是线性流程，无并发会话）。`init/save/clear`。

### 1.3 `template_engine.dart`：glue 升级

注入的 `window.Flashcard` 从「单向 `post()`」扩成：

- `call(method, params)` → Promise，请求带自增 id，`pending[id] = {resolve, reject}`
- `on(evt, fn)` + `__emit(evt, jsonStr)`：壳 → Web 事件
- `__resolve(jsonStr)`：壳 → Web 回执，按 id 兑现 Promise
- **老方法全部保留**（`answer` / `tts` / `getState` …），向后兼容

`buildPage()` 新增 `String workflowJs = ''`；非空时在 `script.js` 之后多注一段 `<script>workflow.js</script>`。

### 1.4 `webview_bridge.dart`：路由 + 能力

- `attach(ctrl)`：绑定宿主控制器（回执/事件要 `runJavaScript`）
- `emit(event, data)`：壳 → Web 事件推送
- `handleMessage` 新增 `rpc` 分支：**不走 messages 流**，直接 `dispatch` + `runJavaScript` 回执
- `_registerCore()` 注册壳能力：`ping` / `card.current` / `state.kvGet` / `state.kvPut` / `session.save` / `session.load` / `session.clear` / `sys.log`

> 验证：`git diff` 逐行比对，重写**没丢任何原逻辑** —— TTS 那套 `TtsOptions.parse(data)` / `tts.speak` / `tts.stop` / `tts.speakSeq` 一字不差，纯增量。

### 1.5 模板包加载 workflow.js

- `deck.dart`：`CardTemplate` 加 `String workflow`
- `deck_repository.dart`：`_templateFiles` 加 `workflow.js`；两个 loader 都读它（缺了返回 `''`）
- `manifest.json`：`files.workflow = "workflow.js"`

## 2. 阶段 3：workflow.js 试点（拿拼写轮开刀）

### 2.1 新增 `templates/bubei_dark/workflow.js`

属于**卡牌包**的一层，不属于壳：

- 会话断点：`saveNow` / `saveSoon`（400ms 节流）/ `clear`，走 `Flashcard.call('session.save')`
- 生命周期：`FC.on('lifecycle.pause', …)` → 立刻落盘
- **拼写轮整轮状态机**（从 script.js 迁入）：`srPool` / 三次机会 / 错词放队尾 / 三种形态（句子·单词·语篇）
- 每步 `saveSoon(snapshot)` 落盘：`{kind:"spell", pool, done, total}`
- 覆盖 `FC.startSpellRound`

### 2.2 `script.js` 瘦身

- 删掉拼写轮状态变量 + 全部 `sr*` 函数 + `FC.startSpellRound`（**-340 行**，1602 → 1284 行）
- 暴露渲染原语：`FC.helpers = { speak, blankSentence, ttsWord }`，供 workflow.js 复用
- 根点击监听：`if (e.target.closest(".fc-spellround")) return;`（块内事件归 workflow）
- 键盘监听：`srOn` 守卫换成 `.fc-spellround` 可见性判断
- **降级兜底**：若 `FC.startSpellRound` 仍不是函数（模板包没带 workflow.js），塞一个「立刻 `spellDone`」的实现，避免整场卡死

### 2.3 边界

## 5. 风险

- **无运行时验证**：`node --check` 只保语法，不保行为。拼写轮交互、RPC 往返、落盘时机都要真机过一遍。
- **workflow.js 依赖 `FC.helpers`**：script.js 若晚于 workflow.js 加载（当前不会，注入顺序固定），helpers 为空会退化 —— 已做 `|| {}` 兜底。
- **老安装目录不重新 seed**：用户公共目录里的模板不会被覆盖，老 `script.js`（带内联拼写轮）继续跑，新特性不生效但不出错。要推新模板得手动「重载模板」或删目录重 seed。
