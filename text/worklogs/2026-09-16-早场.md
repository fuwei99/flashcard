# 2026-09-16 早场

commit: `7c4ee9f`（前一条 `04d14bb` 是语篇按钮收起的修补）

## 本场目标

把「拼写」从「顶栏随手练」升级成**一轮走完的正式拼写轮**。

前一条 `afc1355` 只做了顶栏 `abc` 的当场拼写（一个输入框 + 一个词）。
本场要做的是：**一轮背诵 / 复习走完，可选进入一整轮拼写**，逐格输入、
三种形态、三次机会、循环到全过。

需求原话（要点）：

> 拼写是 `_ _ _ _ _` 这样子，显示有多少个字母空缺
> 一轮背诵/复习之后可以选择是否拼写，不强制，可以选「开始拼写」和「跳过」
> 拼写里含 语篇拼写 和 句子拼写，两个都显示中文意思；单独的拼写只在没有句子的时候出现
> 语篇拼写放在最后
> 单卡下两个按钮：左边跳过（直接显示答案，看答案后点继续），右边忘记了（显示答案，放后面重新拼写）
> 拼写总共三次机会，三次全错默认忘记放到后面重新拼写

后续确认补的：

- 顶栏 `abc` **保留**（那是随手练，跟正式轮不冲突）
- **真·逐格输入**，**不给首字母**
- 三键中间再加一个**提示**（点了 TTS 读一遍单词）
- 拼写结果**不写 FSRS**，轮内无限循环到全过
- 标熟的词**跳过**
- 变形词：**拼文中实际形式**（不是拼原形）
- 中文释义**全部显示**
- 「一轮」= 背诵一轮 / 复习一轮，**各一次**

## 1. 核心决策：循环跑在模板里，不跑在 Dart 里

拼写轮有三条路可以放：

| 方案 | 代价 |
|---|---|
| A. 塞进 `StudySession` 的重测池 | 要动 `_modesFor` / `_passedModes` / `_startMode` 一整套毕业判定，风险大 |
| B. Dart 逐条驱动（每条 mountCard 一次） | 要给 bridge 加一套「拼写条目」的挂载通道，mounter 得认识合成卡片 |
| C. **一次性把整轮条目灌给模板，循环在 JS 里跑** | 只需一个 `startSpellRound` + 一个 `spellDone` 回报 |

选 **C**。理由：

- 拼写轮**不写 FSRS**、不影响调度，本质是一段独立的练习循环，
  跟 `StudySession` 的「单元 → 考法 → 毕业」主线没有耦合；
- 逐格输入的 UI 天然属于模板（HTML/CSS 画格子比 Flutter widget 省事得多）；
- Dart 侧只剩「什么时候问」和「问完往哪走」，两个钩子。

代价：`script.js` 多了 ~260 行。可接受。

## 2. Dart：StudySession 的两个钩子

新增两个阶段：

```dart
enum SessionPhase { passage, passageCloze, learn, choice, cloze,
                    spellPrompt,   // 等用户选「开始拼写 / 跳过」
                    spell,         // 模板里跑，等 spellDone
                    done }
```

### 什么时候问

`StudyPlanner.wordPlan` 保证**复习段排在新学段前面**，所以分界线就是
「前导 `isReview == true` 的单元个数」：

```dart
var n = 0;
for (final u in units) { if (!u.isReview) break; n++; }
_leadingReviewCount = n;
```

`_nextUnit()` 里插两个检查点：

1. `_unitIdx == _leadingReviewCount && _unitIdx < units.length`
   → 复习段刚走完、后面还有新学段 → 问复习这轮的拼写；
2. `_unitIdx >= units.length` → 全部走完 → 问最后一场（新学段）。

两个标志位 `_reviewSpellDone` / `_finalSpellDone` 各管一次，不会重复弹。

边界情况：

- 只有复习单元（`_leadingReviewCount == units.length`）→ 第 1 条不成立，
  最后一场就是复习那轮，卡从 0 取起；
- 只有新学单元（`_leadingReviewCount == 0`）→ 第 1 条不成立，最后一场取全部。

### 问完往哪走

```dart
bool _spellReturnsToUnits;  // true = 接着开下一个单元；false = 整场结束
void beginSpell()  { phase = SessionPhase.spell; }
void endSpell()    { _spellReturnsToUnits ? _startUnit() : phase = done; }
```

`_spellReturnsToUnits` 这个布尔是整个衔接的关键 —— 在**复习/新学边界**上是
`true`（拼完继续学），在**全部走完**时是 `false`（拼完收工）。

### 进度回传

拼写轮的进度条在模板里，原生顶栏那条进度得跟上，所以模板每次换题回报一次：

```js
FC.spellProgress(done, total)  →  {type:"spellProgress"}
```

`StudySession.setSpellProgress(done)` 更新 `_spellDoneCount`，
`doneInRound` 在 spell 阶段返回它。

## 3. Dart：拼写条目怎么编排（ReviewScreen）

三种形态，按卡片的字段能力分流：

| kind | 触发 | 给模板什么 |
|---|---|---|
| `sentence` | 有 `sentence_en` | 原始例句 + `word` + 中文释义 |
| `word` | **没有** `sentence_en` | `word` + 中文释义 |
| `passage` | 该卡所属单元的语篇里有它 | 语篇正文 + 文中**表面形式** + 中文释义 |

排序：`[...sentence, ...single, ...passage]` —— 语篇拼写**压最后**。

两个细节：

1. **变形词交给模板挖**。Dart 不负责把例句里的词抠成空 ——
   模板里现成的 `blankSentence()` 已经能认 `<u>` 标记、原形整词、
   以及词干+后缀白名单三种情况，返回 `{text, answer}`，
   `answer` 就是文中那个变形形式。复用比重写省事，也不会两处逻辑打架。

2. **语篇拼写的「表面形式」要 Dart 找**。`PassageSegment` 有
   `surface` / `lemma` 两个字段（`[prevailed|prevail]` 这种写法），
   按 lemma 匹配回 surface，模板拿去在正文里抠空。

标熟的词在 `_buildSpellItems` 里直接 `continue` 掉。

中文释义用 `meaningFull`（词性 + 释义，多义项用「；」连），不是 `meaningPlain` ——
需求明确说了「全部显示」，`meaningPlain` 会剥括号、也容易把答案写脸上，
这里不需要防泄题（本来就是要看着中文拼）。

## 4. 模板：逐格输入怎么做的

**真 input 藏在屏幕外，格子画在 DOM 上。**

```html
<div class="fc-sr-prompt"></div>
...
<input class="fc-sr-input" ...>   <!-- position:fixed; opacity:.01 -->
```

```css
.fc-sr-input {
  position: fixed; left: 0; bottom: 0;
  width: 100%; height: 1px;
  opacity: 0.01; color: transparent;
  font-size: 16px;   /* <16px 安卓会自动放大页面 */
}
```

- `input` 收键盘，`input` 事件里过滤非字母、截断到答案长度；
- 每个字符画一格 `.fc-sr-slot`（CSS `border-bottom` 当前划线）；
- 填满最后一格 → 自动判定；
- 点题干区域 → `srFocus()` 把键盘唤回来（输入框没有可见区域，
  焦点丢了用户没法再打字）。

为什么不给 N 个 `<input maxlength=1>`：跨格退格、自动前进、中文输入法
在移动端全是坑，而且**本机没有任何 JS 引擎可以试**（见下），
一个可控的隐藏 input 是能盲写的最稳形态。

### 三种形态共用一套骨架

`srRender()` 算出 `{题干, 答案}`：

- `sentence` → `blankSentence(item.sentence, item.word)`
- `passage` → `srBlankPassage(item.passage, item.surface)`
- `word` → 无题干，答案 = `item.word`

题干里的 `______` 被切成两段，中间插 `.fc-sr-slots` 容器（**空占位内联在句子里**）；
没有挖空（`word` 形态）就另起一行放格子。

### 三次机会 + 三个按钮

```
跳过     → 揭答案 → [继续] → 出队，srDone++
提示     → TTS 读一遍单词，srTries++
忘记了   → 揭答案 → [继续] → 放到队尾，后面重来
拼错     → srTries++；还有机会就红一下清空重输，没机会就揭答案 + 放队尾
```

`srTries >= 3`（含提示消耗的次数）→ 自动转成「忘记了」。
揭晓答案后 `srPending` 非空，三个动作按钮收起、`[继续]` 亮出 ——
对应需求那句「看答案后可以点击继续」。

池子用 `srPool`：队首是当前，答对/跳过 `shift()`，忘记 `shift()` 后 `push()`。
池空 = 整轮结束 → `FC.spellDone()`。

顶栏另有「结束拼写」出口，中途想走随时能走（需求没提，但不给出口
意味着必须拼到全对才能退出，太狠）。

## 6. 顺带修的：语篇两阶段不该有标熟/拼写按钮

点「熟」会拿**空 card id** 往 KV 里写，点 `abc` 会拿空串比对。

1. CSS：`[data-mode="passage"|"passage_cloze"] .fc-top-actions { display:none }`

只修 CSS 不够 —— 改样式的人未必知道背后有「card 必须非空」这条前提。

## 坑与教训

1. **「一轮」的粒度要问清楚**。我一开始按「一整场 session」理解，
   用户澄清是「背诵一轮 / 复习一轮」各一次 —— 这是 `StudyPlanner`
   把复习段和新学段拼成一个 units 列表埋下的歧义。
   最后靠「前导 `isReview` 个数」切分，不用改 planner。

2. **本机依然没有任何 JS 引擎**（node / deno / qjs / d8 / bun 全无），
   `script.js` 只能靠括号深度 + 剥注释兜底。
   本场 `script.js` 326/326、深度收尾 0、越界 0；四个 Dart 文件大括号全平。
   **但真语法错误抓不出来** —— 装机第一件事就是点一轮拼写实测。

3. **模板三份 md5 必须对齐**：`/mnt/Flashcard/templates/`（设备立即生效）→
   仓库根 `templates/`（CI 真源）→ `app/assets/templates/`（CI 覆盖目标）。
   本场三方 md5 一致。

4. **隐藏 input 的 `font-size` 不能小于 16px** —— 安卓 WebView 会
   自动放大整个页面，`opacity: 0` 也不行。用 `0.01` 而不是 `0`，
   某些机型 `opacity: 0` 的元素拿不到焦点。
