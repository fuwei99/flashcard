## 一、架构决策（这节比代码重要）

### 1. 排课器 ≠ 记忆模型

把系统拆成两层：

```
① 排课器 Planner   回答「今天给谁」—— 日预算 / 优先级 / 欠账不累积
② 记忆模型 FSRS    回答「这个词多熟」—— 纯函数，不懂今天和考试
```

**为什么**：之前所有毛病的根源是两层揉在一起。FSRS 是纯函数
`(CardState, Rating) → CardState`，硬要它管「今天能做多少」就会写出
「每改一次需求就动一次算法」的耦合代码。`kMaxInterval = 365` 就是这种补丁的历史遗留。

### 2. 出队唯一途径 = 手动标熟

**推翻的方案**：曾设计 `matured`（FSRS 间隔 > 剩余天数 → 自动毕业）。

**推翻理由**：天赢指出「不只是为了考研才背的」——考完还要继续用。
所以不做自动毕业，词只会在队列里间隔越拉越长，永不自动扫地出门。

副产品：考试从「内核」降级为「可选叠加层」（冲刺模式），随时开关不影响数据。

### 3. 不做撤销按钮

**推翻的方案**：顶栏加 `↶`，维护会话历史栈 + 回滚 FSRS 落盘。

**推翻理由**：正面三档只是「预判」（`to-meaning`，不落盘），
到词义页才是真正提交。两段式本身就让手滑可救。少一个按钮 = 少一坨状态管理。

## 二、修复的 Bug

### 🔴 1. FSRS 三档评分从来没生效（核心）

`review_screen.dart` 两处落盘都写死 `Rating.good`：

```dart
69:  if (willGraduate) _write(id, Rating.good);
74:  if (_session.graduated.contains(id)) _write(id, Rating.good);
87:  widget.store.putState(cardId, review(st, r));   // review() 全项目唯一调用点
```

**后果**：`_stabilityAfterForget()` 和 `hardPenalty` 是**死代码**，
稳定性只涨不跌 —— 一个词实际忘了五次，在调度器眼里每次都是「记得很好」。

**修法**：保留「毕业才落盘」的严谨（中间状态不污染），但毕业时按本轮挣扎程度算评分。

```
StudySession._effort[cardId]  (只增不减)  +  ratingFor(cardId)
    一次过     -> good    稳定性正常涨
    费了点劲   -> hard    增长量打 2.3 折
    硬骨头     -> again   稳定性下调，明天必须再见
```

### 🟡 2. `kW[17]` 越界

```dart
final sMin = s / math.exp(kW.length > 17 ? kW[17] : 2.0);
```

`kW` 只有 17 项（w0~w16），`17 > 17` 永假 → 永远走 fallback 的 2.0，
遗忘惩罚过重（稳定性只剩 13.5%）。而那个 2.0 是拍脑袋的，不是 FSRS 论文值。

改成显式常量 `kForgetRetainExp = 1.5`（约剩 22%），可调、可解释。

### 🟡 3. 例句 TTS 念 HTML 标签

`sentence_en` 形如 `The course requires <u>intensive</u> study...`，
按钮直接 `data-tts="{{sentence_en}}"` → 系统 TTS 字正腔圆念出 "less-than-u-greater-than"。

修法：在 `webview_bridge` 的 `tts` 分支统一剥标签（**所有牌组受益，不只 bubei_dark**），
`script.js` 里再加一道防御。

### 🟡 4. `data-pre=again` 时手滑不可逆

原 CSS：

```css
.fc-root[data-pre="again"] .fc-actions-back .fc-again{display:none}
```

- 手滑 `忘记→记得`：词义页有「记错了」✅ 能救
- 手滑 `记得→忘记`：`pre=again` → 「记错了」被藏 → 只剩「下一词」→ 只能认 again ❌

修法：补一个只在 `pre=again` 时露出的「记对了」按钮（`data-rating="good"`），两边对称。

### 🟡 5. `markDone()` 在未毕业时也计数

原来 `await widget.settings.markDone()` 在 learn 轮每次都调，
模糊/忘记（未毕业）也算进今日进度 → 今日进度虚高。

改成只在真正毕业（`graduated` 且未 `_written`）时计数。

## 三、基建修复

### ⚠️ `app/assets/templates/` 是副本，不是软链

差点翻车：改了根 `templates/bubei_dark/` 三个文件，
但 `app/assets/templates/bubei_dark/` 是独立副本，**根本没进 APK**。
`diff` 确认差异恰好只有本次编辑，说明之前是镜像，现在过期了。

修法：CI 构建前强制同步，确立根目录为唯一真源。

```yaml
- name: Sync templates & decks into app assets
  run: |
    mkdir -p app/assets/templates app/assets/decks
    [ -d templates ] && cp -r templates/. app/assets/templates/ || true
    [ -d decks ]     && cp -r decks/.     app/assets/decks/     || true
```

以后只改根 `templates/` 和 `decks/` 就够了。

## 七、第二轮（19:13 – 19:20）：重测流程返工

天赢实测后提了三条，都是真问题：

### BUG-007 · choice 选项没有词性

只有中文释义，四个释义摆一起没法选。
`_choicesFor()` 只取 `meaning`，把 `pos` 丢了。

→ `choices` 扩成 `{text, pos, right}`，`script.js` 渲染成左侧淡色斜体小标签。

### BUG-008 · choice 和 cloze 挨着考同一个词

原顺序 `A-choice → A-cloze → B-choice → B-cloze`，
刚做完 A 的英选中，紧接着 A 的例句挖空 —— **上一题选项里刚见过这个词**。

→ 重测拆成两轮，一次过完：`choice 轮（全部卡）→ cloze 轮（全部卡）`。

### BUG-009 · 答错后不给看词义（原描述有误，已更正）

天赢原话：**「之前答错了不会进入词义页面」**。

choice / cloze 答错后直接翻篇，既不显示完整词义，也不给学习机会。
而这张卡后面还要重考 —— 变成「选错 → 下一题 → 又考 → 又错」的机械循环。

→ **答错切到词义页**（复用 `read` 的 `.fc-back`：词 + 音标 + 词性 + 释义 + 例句），
点「下一词」继续。这张卡**仍然会被重考**，直到 choice + cloze 两个考法都过。

**实现要点**（模板侧）：
- `script.js` 的 `pick()`：答错 `root.setAttribute("data-state","back")`
- `style.css`：`.fc-root[data-state="back"] .fc-back{display:block}`，
  并在 `data-state="back"` 时藏掉 `.fc-choice` / `.fc-cloze` 和「已掌握」绿勾
- 按钮沿用 `.fc-actions-next` 的「下一词」，不复用 read 的「记错了/下一词」

### 恢复循环重考（这才是设计意图）

- `submitRetest` 答错不记通过，后面轮次继续考
- `_advance`：cloze 阶段走完 → 查池内是否全部 `_allPassed`
  全过 → 毕业；还有没过 → `round++`，回 choice 阶段
- `_startChoice` / `_startCloze` **只考「还没过」的考法**，已过的不再重考
- 保留两阶段顺序：先全部 choice，再全部 cloze

### 同一轮的其他调整

- `_onMsg` 的落盘遍历 `graduated` 全部未落盘的卡
  （重测走完是「整池一起毕业」，只写当前那张会漏）
- 顶部进度带轮次：`重测 R1·选义` / `重测 R1·填空`

## 八、本轮教训（两条，第二条更疼）

**一、「出错就重来」和「出错就补课」是两回事。** 前者是惩罚，后者是学习。
答错之后，该做的是把词义完整摊开让人学一遍，然后再考 —— 而不是机械重复。

**二、用户的话没听准，别急着改核心逻辑。**
我把「答错了不会进词义页」读成了「答错不要重考」，
第一版 `e52870e` 直接把整套循环重考机制删了，还把 `retestModes` / `_passedModes`
说成「死代码」。天赢一句「答错必须重考，一直循环到两个测验都答对了为止」把我打回来。

**以后遇到语义模糊的需求，先复述一遍确认，再动手。**
