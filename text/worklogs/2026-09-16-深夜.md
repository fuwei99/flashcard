## 1. 标熟（known）—— 永久出队 + 可撤销

### 存储放哪（关键决策）

放 **卡牌私有 KV**（`CardStore._kv[id]['known']`），**不塞进 `CardState`**。

理由：标熟是「人判定我会了」，不是调度事件。塞进 CardState 有两个坏处：

1. 污染 FSRS 数据 —— 撤销标熟时得把 stability/difficulty/due 全还原，还原不干净就毁进度；
2. `CardState.state` 已经有一套语义（new/learning/review/relearning），再塞一个 `known` 进去，出队判断会变成多条件叠加，越写越乱。

放 KV 的话，撤销 = 删一个 key，调度历史原样不动。干净。

### 新增 API

```dart
bool isKnown(String id) => _kv[id]?['known'] == true;
void setKnown(String id, bool v) => putKv(id, 'known', v);
```

`putKv` 本来就走追加日志 + prefs 兜底，不用另写持久化。

### 队列过滤 —— 一共四处，少一个就漏

| 位置 | 管什么 |
|---|---|
| `CardStore.dueQueue` | 新卡 + 到期混合队列 |
| `CardStore.reviewDue` | 纯到期队列（`StudyPlanner` 走它） |
| `StudyPlanner.newUnits` | 新学段 |
| `page_list_screen._startReview` | 书内「顺序 / 乱序背诵」 |

漏掉任何一处，标熟的词就会从另一个口子爬回来。

另外 `countLearned` 把标熟也算「已处理」，否则章节进度条会把标熟词算成没背。

## 2. 拼写（spell）—— 模板内当场测验

**没有动会话状态机**（`StudySession` / `StudyMode.spell` 保持原样）。

理由：顶栏点 abc 是「当场练一下」，不是会话里的一个考法。硬塞进 `retestModes` 会牵动
`_modesFor` / `_startMode` / 重测池毕业判定一整套逻辑，风险远大于收益。
所以做在模板里，纯前端，答完回原状态。

### 新增

- `template.html`：`fc-spell` 面（中文提示 + 输入框 + 红绿结果行）、`fc-actions-spell` 底栏。
- `script.js`：
  - `enterSpell()` 记下 `spellPrevMode / spellPrevState`，**返回时原样还原**
    （从词义页进的就回词义页，从正面进的就回正面）；
  - `spellCheck()` 小写比对，空输入不判错（免得白挨一刀），答完念一遍正确发音；
  - 输入框回车 = 检查；检查完按钮文案变「返回」。
- `style.css`：`.fc-root[data-mode="spell"]` 一套显隐，跟现有 `data-mode` 选择器同构。

### 一个容易踩的坑

全局键盘监听会抢空格 / 回车（`toMeaning`）。spell 模式下必须 **guard**：

```js
if (root.getAttribute("data-mode") === "spell") return;
```

不加这行，在输入框里敲空格就直接翻页了。

## 4. 桥接：模板怎么知道这张卡标没标熟

`WebViewBridge.mountCard` 的 `cardJson` 加一个 `kv` 字段：

```dart
'kv': card == null ? <String, dynamic>{} : store.kvOf(card.id),
```

模板 `mount()` 里读 `card.kv.known` 点亮按钮。

**不传就是永远灰的** —— 模板的 `FC.getState` 读的是 `window.__FLASHCARD_KV__`，
那玩意儿只在骨架页构建时塞一次（空对象），切卡不会更新。所以必须走 cardJson。

标熟落盘复用现成的 `FC.setState` 通道 → 宿主 `putKv`，一行新代码都不用写。

## 坑与教训

1. **模板三份必须 md5 对齐**：`/mnt/Flashcard/templates/`（设备立即生效）、
   仓库根 `templates/`（CI 真源）、`app/assets/templates/`（CI 覆盖目标）。
   本场先改 `/mnt`，再 `cp` 回仓库两份。
2. **括号配平脚本会误报**：注释里的 `1) 2) 3)` 被算成多余右括号。
   正确姿势 —— 剥掉 `//` 行注释再数。本场 5 个 Dart 文件 + 3 个模板文件全部平衡
   （`card_store.dart` 剥注释后 174/174，`script.js` 827/827，深度 0）。
3. **本机没有任何 JS 引擎**（node / nodejs / deno / qjs / js / d8 / bun 全无），
   `script.js` 只能靠括号深度兜底，**真语法错误抓不出来**。装机验证时必须实测拼写面板。
