## 1. 核心分层：排课器 ≠ 记忆模型

这是整套架构的地基，也是之前所有毛病的根源——两层揉在一起了。

```
┌──────────────────────────────────────────────┐
│ ① 排课器 Planner        【今天给谁】           │
│    · 日预算（复习位 / 新词位）                 │
│    · 到期队列 + 优先级排序                     │
│    · 欠账不累积                                │
│    · 冲刺模式（可选叠加层，不写进内核）          │
└───────────────────┬──────────────────────────┘
                    │ 今日队列
┌───────────────────▼──────────────────────────┐
│ ② 记忆模型 FSRS-lite    【这个词多熟】          │
│    · 纯函数：(CardState, Rating) → CardState   │
│    · 完全不懂「今天」「考试」「预算」            │
└──────────────────────────────────────────────┘
```

**为什么必须拆**：FSRS 是纯函数，硬要它管"今天能做多少"就会写出"每次改需求都动算法"的耦合代码。
`kMaxInterval = 365` 就是这种补丁的历史遗留。

## 2. 调度规则（v2 已定）

### 出队只有一条路：**手动标熟**

```
一个词只有两种命运：
  ① 手动标熟     → 永久出队（可撤销）
  ② 继续在队列里 → 间隔越拉越长，永不自动毕业
```

**不做** `matured`（间隔 > 剩余天数自动毕业）——因为考完还要背，不能自动扫地出门。

### 每日预算

```
复习位 X / 天 + 新词位 Y / 天（用户可调）
  到期量 > 预算 → 只做优先级最高的那批
  到期量 < 预算 → 补新词
```

**欠账不累积**：今天没做完的到期词，明天重新排队，**不叠加**。否则雪球越滚越大，
就是"每天复习不完"的死因。

### 优先级（预算不够时谁上）

```
优先级 = 逾期天数 × 真题词频 × (1 + 错误率) × 文章里猜错过 ?
```

考研只背 2000 词，这个排序直接决定分数。

### 冲刺模式（可选叠加层）

```
日常模式（默认）        冲刺模式（可随时开关，设目标日）
  · 预算自定义             · 权重倾斜到高频词
  · 按逾期排序             · 压短间隔，考前拉一波
  · FSRS 自由跑            · 关掉即回日常，数据不受损
```

内核只多读一个 `sprint: {target_date, weight_boost}` 字段，算法层不碰。

### 参数建议

不赶考试了，`desired_retention` 可从 0.90 降到 **0.85**，复习量直接降一截。

## 3. 三档评分 → FSRS（2026-09-13 修复）

### 🔴 修复前的 bug

`review_screen.dart` 两处落盘都写死 `Rating.good`，而 `review()` 全项目只有那一个调用点。
**后果：FSRS 永远只收到 good，`_stabilityAfterForget` 和 `hardPenalty` 是死代码，
稳定性只涨不跌 → 伪 FSRS。**

### ✅ 修复后：毕业时按本轮「挣扎程度」选档

| 本轮表现 | 写的评分 | FSRS 行为 |
|---|---|---|
| learn 轮一次「记得」就过 | `good` | 稳定性正常上涨 |
| 进过重测池，第 2 轮全过 | `hard` | 增长量打 2.3 折 |
| 重测答错 ≥2 次 / 正面点过「忘记」 | `again` | 稳定性下调，明天必须再见 |

实现：`StudySession._effort[cardId]`（只增不减）+ `ratingFor(cardId)`。
**保留"毕业才落盘"的严谨**（中间状态不污染），但毕业时评分是算出来的，不是写死的。

### 遗忘惩罚系数

```
kForgetRetainExp = 1.5   // S_min = S / e^1.5 ≈ 保留 22%
```

原代码 `kW.length > 17 ? kW[17] : 2.0` 越界（kW 只有 17 项 w0~w16），
永远走 fallback 2.0 —— 惩罚过重（只剩 13.5%）。改成显式常数，可调。

## 4. 学习 / 复习闭环

```
【导入】词表 → 分级自测（熟 / 模糊 / 不认识）→ 待背池
                     │        一步省掉 2/3 工作量
【每日】排课器（日常 or 冲刺）
   预算：复习 X + 新词 Y
   ├─ 到期池（逾期优先）→ 取前 X
   └─ 新词池（按真题词频降序）→ 补齐 Y
   ★ 欠账不累积
                     │
        ★ 今日任务：复习 47 · 新词 40   ← 书架级入口，跨书汇总
                     │
【学习轮 learn】新词
   正面(词) → 三档自评(忘记/模糊/记得) → 词义页 → [记错了 / 记对了? / 下一词]
   ├─ 记得 → 进复习周期（due = 明天）★ 不是"永久毕业"
   └─ 模糊/忘记 → 进重测池
                     │
【重测轮 retest】池内词，每词两个考法
   choice(英→中选义) → cloze(例句挖空选英词) → [spell 拼写，待做]
   两个全过 → 毕业进周期
   任一错 → 留池，下一轮重考（循环到过）
                     │
【复习轮 review】到期词
   同套流程 → FSRS 更新 → 排下次（间隔越来越长）
                     │
【任意时刻】☆收藏 ｜ 熟=标熟 ｜ abc=拼写 ｜ ⋯ 更多
                     │
【每日结束】写 status.json + 日报
```

### 术语澄清（代码里曾经混用）

| 词 | 含义 | 效果 |
|---|---|---|
| `graduated` | **本轮通过** | 写 CardState(state=learning, due=明天) |
| `known` | **手动标熟** | 永久出队，可撤销 |
| ~~`matured`~~ | ~~自动毕业~~ | **v2 已废弃** |

## 5. 按钮体系（对齐不背单词）

顶栏：`13/20` ｜ `☆收藏` ｜ `熟` ｜ `abc` ｜ `⋯`

| 按钮 | 行为 | 状态 |
|---|---|---|
| ☆ 收藏 | 进全局生词本，跨书 | 待做 |
| 熟 | 标熟 = 永久出队（可撤销） | 待做 |
| abc | 当场拼写测验 | 待做（`StudyMode.spell` 已定义未实现） |
| ⋯ | 编辑释义 / 加笔记 / AI 问词 / 看真题出处 / 移入自定义词单 | 待做 |

**不做撤销按钮**。理由：正面三档只是"预判"（`to-meaning`，不落盘），
到词义页才是真正提交 —— 手滑本来就能救。

底栏 tab：`词组搭配` ｜ `近义` ｜ `词根` ← 数据字段要加 `synonyms`（暂无）

### 「记对了」反悔位（2026-09-13 加）

原 CSS `.fc-root[data-pre="again"] .fc-actions-back .fc-again{display:none}`
把「记错了」藏了，导致**手滑 `记得→忘记` 单向不可逆**。
现在 `pre=again` 时露出「记对了」按钮（`data-rating="good"`），两边对称。

## 6. 数据分层（长期使用的地基）

```
① 词条库 LemmaStore   主键 = word（小写 lemma）
     释义 / 音标 / 词根 / 例句 / AI 笔记 / 用户笔记 / 来源标签 / 收藏 / 标熟
     ★ 跨书共享：一处加笔记，处处显示（干掉"加笔记要付费"）

② 调度库 ScheduleStore  主键 = word
     FSRS 状态（stability / difficulty / reps / lapses / due / state）

③ 牌组库 DeckStore    书 → 章 → 页，纯内容组织，不持有状态

④ 日志 EventLog       append-only，每次评分一行（统计 / 监督 / 回滚）

⑤ 快照 status.json    给外部读（见 §8）
```

**当前缺口**：`CardStore` 把调度和 KV 混在一起，词条数据散在 deck json 里。
需要抽出来，让"词"成为一等公民。

## 7. 内容生产线（AI 侧）

```
真题 PDF / 用户贴的段落 / 红宝书词表
   ↓ 提取 & 过滤（超纲词剔除、对照大纲词表）
   ↓ AI：挑 N 词 → 写一篇贴考研题材的文章（词必须自然出现，不许硬塞）
   ↓ 生成：文章 HTML + 每词释义/音标/词根/真题原句/AI 笔记 + 来源标注
   ↓ 输出 deck JSON
用户：导入 → 读文章 → 点词 → 评分
```

- 名词来源可标：`真题 2022 Text1` / `红宝书 Unit 32` / `AI 例句`
- **文章牌组**（待做）：新模板 `article_reader`，点击划线词悬浮释义 → 三档评分
- 密度建议：**15~20 词/篇**，40 词太密阅读体验差
- 质量命门：最容易出的毛病是"为塞词把文章写成单词表"，需人工抽检

## 9. TTS 架构（v0.9 已实现）

```
Flashcard.tts(text, lang)      ← 牌组只发这一句，不关心底下是谁
        │
   WebViewBridge（剥 HTML 标签）
        │
   TtsService.speak(text, lang)          ← lib/services/tts_service.dart
        ├── 单个英文词 → cache/tts/ 命中 → just_audio 秒播（零延迟）
        │                 未命中 → POST {base}/audio/speech → 收全字节落盘 → 播
        └── 长句       → POST 响应字节流直接喂 StreamAudioSource
                          → 边收边播，不攒完整包
        └── 兜底       → flutter_tts（在线没配置 / 合成失败时）
```

- 在线引擎 = OpenAI 兼容接口：`POST {base_url}/audio/speech`，
  `model / voice / base_url / api_key / speed / response_format` 全可配。
- 缓存键：`word + lang + model + voice + speed` 取 sha1 → `cache/tts/<sha1>.<fmt>`，
  换音色/模型/语速自动重建，不会串音。
- 单词（纯字母、无空格、≤40 字符）走缓存；其余文本走流式，不缓存。
- 设置页（我的 → TTS 引擎）：引擎开关 / base_url / key / model / voice / 语速 / 缓存开关 / 测试发音。
- `manifest.tts.auto_play`（写了但没人读）要接上：进卡自动朗读单词。

### 已修：例句 TTS 念 HTML 标签

`sentence_en` 带 `<u>intensive</u>`，原来直接喂 TTS 会念出尖括号。
现在在 `webview_bridge.handleMessage` 的 `tts` 分支统一剥标签（所有牌组受益），
`script.js` 里也加了一道，防御性双保险。

### 观察项（非 bug）
- 重测轮 `_startRetest()` 会 `_passedModes.clear()`：上轮过了一个考法，下轮两个都要重考。
  符合「两个都过」的设计，但略费时。
- 重测轮是**无限循环直到全过**，没有「跳过」出口。词太生时可能卡住，考虑加逃生口。
- 首次间隔恒为 1 天（`kLearningInterval`），之后按 FSRS 递增（约 1 → 7 → 20 → 50 → …）。
- `kMaxInterval = 365` 对长期使用偏保守，可调。
